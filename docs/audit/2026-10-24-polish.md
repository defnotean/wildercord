## 2. Server operations (the nightly crash)

- **The watchdog kills the server every night, 04:03–04:56** (crash reports for Oct 11–22). `backup_world.ps1` runs
  `Compress-Archive` on the ~16 GB world and starves the server thread past `max-tick-time=60000`. On Oct 22 the zip
  finished at 04:48:11 and the crash came at 04:48:16.
- The backup also skips `save-all flush` before copying, so it can miss up to one autosave interval of changes.
- Fix options:
  - Run `save-all flush` first.
  - Replace the zip with an incremental `robocopy /MIR` snapshot, or 7-Zip at low priority with `-mmt=2`.
  - Or set `max-tick-time=-1`.
  - Doing the first two together is the clean fix.
- **The deploy path isn't in git and is inconsistent.**
  - `apply_update.ps1` installs any staged jar with no hash check.
  - `deploy-0130.ps1` falsely reported a failed health check and left the watchdog disabled.
  - Fix: put the deploy and ops scripts under `tools/vps/`, add a SHA-256 check to the auto-install, and write one
    `tools/release.py` that bumps the version, builds on the VPS, runs smoke, tags, uploads and stages.
- **Staging clutter on the VPS:** `deploy-0120/0130.ps1`, `dp.ps1`, `rcon-0100.ps1`, old status and log files, and the
  `pre-0130` backup (once 0.14 is live). `Chunky-Fabric-1.5.3.jar` is unused, since pre-generation is abandoned.
- A player connected with an older client (`syncable attachments wildercord:lesson_pack_view` warning). Consider a
  version check at login with a clear "update your mod" message.

**Batch B status (2026-10-24):** the backup rewrite, the hash-checked auto-install, a generic `deploy.ps1` and their
tests are in [`tools/vps`](../../tools/vps/README.md), and they're installed on the live server. Still open: proof
from a night without a 04:xx crash, `tools/release.py`, the staging clutter and the old zips (they need the owner's OK
to delete), and the login version check.

Separately, `BellShard:58`, `Rimescale:65` and `CinderAntler:72/78` cooldowns compare against `getTickCount()`, which

value.

stop.

**Missing dimension in a key:** `InnRaid.ACTIVE` keys on position only.

## 4. Performance

- **`BondedBlades.tick`:** scans every player's whole inventory every tick (`aura/BondedBlades.java:694-735`). Run it
  every 10–20 ticks or only when the inventory changes.
- **`CinnamonCompanion:157`:** runs a level-wide `getEntities` every 5 ticks. Use the owner's AABB.
- **Client boss models allocate a new `PartPose` every frame during move blends.** Affected: Gravekeeper, AshenStag,
  BellWarden, FrostWyrmling, HollowMatron, LanternBearer, Mojito.
  - A restarted move snaps instead of blending.
  - Fix: extract one shared blend helper that handles both.
- **Other per-frame allocation:**
  - `SerpentRenderer`, the heaviest.
  - `Identifier` built with string concatenation in `CordLayer:64`, `MasterRenderer:40/98`, `RuneMarksLayer:134`,
    `CordStyleLook:41` and `GuiSpellCircle:32-41`. Cache them in static arrays.
  - `SoarWingModel`, `WispRenderer`, `ShieldCircles`, `SpellCircleParticle`, `SigilParticle` and
    `GameRendererMixin:25`.
  - Particle `tick()` rebuilding sprite names in the Camp, Earth, Life, Void and Material particles.
- **`ItemStackBondMixin`:** allocates a name `Component` on every `getHoverName` call for a bonded blade.

## Suggested order

   test.
2. **Batch B — server ops:** the backup rewrite, ops scripts in git, and a hash-checked auto-install. This stops the
   nightly crash.
3. **Batch C — leaks and a11y:** the reset-on-stop registry, plus the `safeTelegraphs`, flash and vignette fixes.
4. **Batch D — test and tooling clean-up:** gate leftovers, dead workflows, payload round-trips and the mount smoke
   class.
5. **Batch E — client performance:** the shared boss-blend helper and the cached identifiers.
6. **Batch F — docs:** AGENTS and handoff, changelog and what's new, the CurseForge description, the README features
   table, then retire the stale roadmaps.
7. **0.14 release:** bump the version, run `release-smoke` once on the VPS, then deploy with a hash check.
